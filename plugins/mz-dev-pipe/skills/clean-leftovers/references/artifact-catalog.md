# Artifact Catalog — Embedded Pattern Reference

Pattern catalog for the five leftover-artifact categories. The detection phase grabs per-category blocks via `grep "^# Category"` anchors and does not read this whole file at once. The cleaner agent does the same per-instance lookup during execution.

Patterns are written as ECMAScript-compatible regex (works with `grep -E`). When a pattern is language-specific, the language is noted; the detection phase applies it only to matching file extensions.

---

# Category A: AI signatures & watermarks

Exact strings or short regex. Match in any source file (any extension). False-positive guard: skip matches inside test fixtures, license headers that legitimately credit AI assistance, or markdown sections explicitly quoting examples.

## Claude Code

- `🤖 Generated with \[Claude Code\]`
- `🤖 Generated with Claude Code`
- `Generated with \[Claude Code\]`
- `Co-Authored-By: Claude <noreply@anthropic\.com>`
- `Co-Authored-By: Claude` (without the email — looser variant)
- `https://claude\.ai/code` (when inside source files, not in legitimate doc references)
- `Claude AI assistance` (footer comments)

## GitHub Copilot

- `// generated by Copilot`
- `// Copilot:`
- `# Copilot generated`
- `<!-- Copilot generated -->`

## Cursor

- `<!-- Generated by Cursor -->`
- `// Generated by Cursor`
- `# Generated by Cursor`
- `Cursor: composer-edit`

## Aider

- `# aider:`
- `# aider chat:`
- `aider/llm:`

## Codex / Codex CLI

- `# codex:`
- `// codex generated`
- `<!-- codex -->`

## ChatGPT / OpenAI

- `// Generated by ChatGPT`
- `# ChatGPT-generated`
- `<!-- OpenAI -->`
- `assistant-message:` (when leaked from a transcript dump)

## Gemini / Bard

- `// Generated by Gemini`
- `# Gemini-assisted`

## Continue.dev / Codeium / Tabnine

- `// continue.dev`
- `// codeium:`
- `// Tabnine:`

## Generic AI identity claims (in docstrings / comments)

- `\bI am (Claude|ChatGPT|an AI assistant|a large language model)\b`
- `\bas a large language model\b`
- `\bI was asked to\b`
- `\bI'll help you (with|by)\b` (when appearing in a code comment, not a prompt)
- `\bAs an AI,? I\b`

## Removal rules

- Delete the entire matched line. If the match is the only content in a comment block, delete the block.
- For commit-message footers (`🤖 Generated with...`, `Co-Authored-By: Claude`): these live in commit messages, not source code, but they sometimes leak into source files via copy-paste. Treat as line-delete.
- Preserve when the file is a documented example of AI artifacts (markdown under `docs/`, `guidelines/`, `plugins/mz-creative/skills/naturalize/`, this skill's `references/`).

# Category B: Pipeline phase markers

Pattern anchors specific to the mz-dev-pipe pipeline plus general agent-orchestration leftovers. Match in any source file.

## Phase notation

- `Phase \d+(\.\d+)?:` — `Phase 1:`, `Phase 2.5:`, `Phase 11:`
- `Phase [A-Z][a-z]+:` — `Phase Setup:`, `Phase Research:`
- `## Phase \d` — markdown heading style
- `Step \d+(\.\d+)?:` — `Step 4:`, `Step 2.3:`

## Task / state placeholders

- `<task_name>` — literal placeholder substring
- `<task[_-]?name>` — variant spellings
- `<YYYY_MM_DD>` — unsubstituted date placeholder
- `\.mz/task/` — path token in non-pipeline source
- `\.mz/reports/`
- `\.mz/research/`

Allow `.mz/...` paths inside this skill's own files, inside any `plugins/*/skills/*/SKILL.md`, inside any `plugins/*/skills/*/phases/*.md`, inside any `plugins/*/agents/*.md`, and inside `guidelines/**`. Detection phase enforces this via path-allowlist.

## Status breadcrumbs

- `STATUS: DONE` — when outside an agent definition file
- `STATUS: NEEDS_CONTEXT`
- `STATUS: BLOCKED`
- `STATUS: DONE_WITH_CONCERNS`

These are load-bearing tokens INSIDE agent definitions (`plugins/*/agents/*.md`) — never edit those. Outside agent definitions they are leftover.

## Dispatch / orchestration leftovers

- `\bdispatched by\b` (in source-code comments, not in agent definitions or skill files)
- `\bper pipeline plan\b`
- `\bfrom planner\b`
- `expert-[a-z-]+-agent` (any expert-* agent name in source-code comments)
- `pipeline-[a-z-]+-agent`
- `// orchestrator says`
- `# agent dispatch:`

## Removal rules

- Delete the matched line if the line is comment-only.
- If the match is part of a longer prose comment that has other content, ask the cleaner to rewrite the comment to drop only the marker phrase (e.g., `// Validate input (Phase 2 work)` → `// Validate input`).
- Never edit inside agent or skill definition files — Phase 3 safety rails enforce this.

# Category C: Planning / generation-process comments

Comments that reference the AI's plan, research, or generation process. Match in source files by comment style.

## Per-language comment styles

- C/Java/JS/TS/Go/Rust/Swift/Kotlin: `//`, `/* */`
- Python/Ruby/Shell/YAML/TOML: `#`
- HTML/XML/Markdown: `<!-- -->`
- SQL: `--`, `/* */`
- Lisp/Clojure: `;`

The patterns below are written for `//` style; the detection phase mirrors them across all comment styles.

## Plan-reference patterns

- `//\s*per\s+plan\b`
- `//\s*per\s+the\s+plan\b`
- `//\s*as\s+per\s+(the\s+)?plan\b`
- `//\s*from\s+(the\s+)?plan\b`
- `//\s*Plan:\s*\d`
- `/\*\s*Plan:\s*\d.*?\*/` (multi-line)

## Research-reference patterns

- `//\s*from\s+research\b`
- `//\s*per\s+research\b`
- `//\s*research\s+phase\s+(found|noted|said)`
- `//\s*research\s+task\s+output\b`

## Phase / implementation-reference patterns

- `//\s*implementation\s+per\s+phase\s+\d`
- `//\s*from\s+phase\s+\d`
- `//\s*phase\s+\d\s+output\b`
- `//\s*TODO\s+from\s+planning\b`

## AI-self-reference patterns

- `//\s*AI\s+generated\b`
- `//\s*generated\s+by\s+AI\b`
- `/\*\s*AI\s+generated\s*\*/`
- `//\s*model:\s*(opus|sonnet|haiku|gpt|claude|gemini)\b`

## Approval-flow leftovers

- `//\s*per\s+user\s+approval\b`
- `//\s*after\s+user\s+approved\s+phase\b`
- `//\s*user\s+approved\s+at\s+phase\s+\d`

## Removal rules

- Always delete the matched line if comment-only.
- If the match is mid-comment alongside genuine WHY content, ask the cleaner to drop only the marker phrase and keep the rest.

# Category D: WHAT-not-WHY candidates (conservative)

Detection here is heuristic; deletion requires per-instance judgment by the cleaner agent. The orchestrator emits candidates with `decision: pending`.

## Candidate types

1. **Restated-code candidate** — single-line comment immediately above a code line where the comment's tokenized content overlaps ≥ 0.7 with the identifiers / keywords in the next non-blank line.

   - `// increment counter\n  counter++` → token overlap 1.0 (perfect match)
   - `# loop through users\n  for user in users:` → token overlap 0.8

2. **Echo-the-name docstring** — first line of a docstring inside `def`/`function`/`fn`/`func` declarations whose tokens overlap ≥ 0.7 with the function name (split on `_` and camelCase boundaries).

   - `def greet_user(name): """Greet user."""` → token overlap 1.0
   - `function calculateTotal(items) { /** Calculate total. */ }` → token overlap 1.0

3. **Trivial inline label** — one-or-two-word comment at end of obvious operation: `// add`, `// subtract`, `// return result`, `// loop`, `// check`, `// done`, `// end`, `// init`.

## Tokenization (for similarity scoring)

- Lowercase.
- Split on non-alphanumeric.
- Drop English stop words: `the`, `a`, `an`, `is`, `to`, `of`, `for`, `and`, `with`, `in`, `on`, `at`.
- Drop common code keywords from the LHS comparison: `def`, `function`, `fn`, `class`, `var`, `let`, `const`, `return`, `if`, `else`.

## WHY content markers (when present, KEEP the comment)

The cleaner keeps a flagged candidate when ANY of these signal WHY:

- Numbers with units: `\b\d+\s*(ms|s|sec|min|hr|day|MB|GB|KB|TB|%|x|×)\b`
- Named references: `RFC\s*\d+`, `CVE-\d{4}-\d+`, `#\d+` (issue/PR refs), `[A-Z]+-\d+` (Jira-style tickets)
- Causal connectors: `because`, `due to`, `to avoid`, `to prevent`, `to work around`, `to satisfy`, `since`, `otherwise`
- Performance / correctness notes: `fastpath`, `slow path`, `race condition`, `not thread-safe`, `requires lock`, `must be`, `cannot be`
- Regulatory / compliance: `GDPR`, `HIPAA`, `PCI`, `SOX`, `regulatory`, `legal requires`
- Surprising-behavior callouts: `surprisingly`, `counterintuitively`, `note that`, `gotcha:`, `caveat:`, `careful:`

When ANY of the above is present, KEEP — even if the comment otherwise looks like a WHAT restatement.

## Removal rules

- Cleaner reads the candidate AND the surrounding context (3 lines before/after).
- If WHY markers present → KEEP, record `decision: kept (WHY content present)`.
- If WHY markers absent AND token overlap ≥ 0.7 → DELETE, record `decision: deleted (pure WHAT)`.
- If token overlap between 0.5 and 0.7 → mark `decision: uncertain` and return `NEEDS_CONTEXT` for that file; the orchestrator escalates uncertain cases via AskUserQuestion only when ≥ 5 uncertain candidates accumulate (to avoid prompt fatigue).

# Category E: Dead code & half-implementations

Structural patterns plus regex anchors. Some require multi-line matching.

## Commented-out code blocks

- ≥ 3 consecutive lines starting with the language's line-comment prefix where the inner text contains code-like tokens.
- Code-like token regex: `=|function|def|class|import|return|if|else|for|while|\(|\)|;|\{|\}|->|=>|::`
- Match if ≥ 2 of the consecutive lines contain code-like tokens.

Example (Python):

```
# user_id = request.user.id
# if user_id:
#     log.info("auth ok")
```

3 lines, all with code-like tokens → match.

## Stub functions

- Python: `def\s+\w+\([^)]*\)\s*(->\s*[\w\[\],\s]+)?\s*:\s*\n\s*pass\s*(#.*)?$`
- Python: `def\s+\w+\([^)]*\)\s*:\s*\n\s*raise\s+NotImplementedError\b`
- Python: `def\s+\w+\([^)]*\)\s*:\s*\n\s*\.\.\.\s*(#.*)?$`
- JavaScript / TypeScript: `function\s+\w+\s*\([^)]*\)\s*\{\s*\}` (empty body)
- JavaScript / TypeScript: `throw\s+new\s+Error\s*\(\s*["']not\s*implemented["']\s*\)`
- Go: `func\s+\w+\([^)]*\)\s*[\w\s\*\[\],]*\{\s*panic\s*\(\s*"not\s+implemented"`

## TODO / FIXME stubs with no implementation

- `TODO:\s*implement\b`
- `FIXME:\s*stub\b`
- `pass\s*#\s*TODO\b`
- `// TODO: implement\s*$`

## Stale removed/deleted markers

- `//\s*removed:\s*\w+` followed by no related code in the next 5 lines
- `//\s*deleted:\s*\w+` followed by no related code
- `#\s*REMOVED:\s*\w+`

## Removal rules

- Commented-out blocks ≥ 3 lines: delete if no live code references the block (e.g., the block's commented-out function name is not called nearby). The cleaner re-judges per-instance.
- Stub functions: delete only when the dispatch's per-file plan flags `decision: delete-stub`. The orchestrator marks `decision: delete-stub` when the stub has zero callers in the scope; otherwise it marks `decision: keep-stub (has callers)`.
- TODO/FIXME stubs: delete the entire function only if zero callers AND zero referenced tests. Otherwise mark `decision: keep-stub`.
- Stale removed/deleted markers: delete the marker line; do not delete surrounding code.
- Unused imports: defer to the linter in Phase 4. Do not auto-edit imports in cleaner waves — linter handles this with full project context.
