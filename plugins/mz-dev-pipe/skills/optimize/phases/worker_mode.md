# Worker Mode

These steps replace the parts of the skill they name; `<PLUGIN_ROOT>/shared/worker-mode.md` governs everything else.

- **Brief.** Read it; `kind` is `change`. Parse the `## Spec` as the argument: `type:`, `scope:`, the target, the metric with its unit and direction, the goal, the measurement command, the correctness command and any iteration cap. `scope` defaults to the brief's `owns`, and `owns` bounds every candidate.
- **Goal Declaration.** A spec missing the metric, its unit, its direction or a target (a number, or "best effort") is a blocker: emit `BUDGET MISSING` and end `STATUS: BLOCKED`.
- **Measurement command.** `measure_command` must come from the spec. Never take the detector's guess or write one yourself: with none in the spec, set `Status: blocked` and name the missing command under `## Blocker`. `correctness_command` comes from the spec, else the brief's `verify`, else the detector. With none, or with `manual`, it is a blocker too.
- **Gates.** The contract (Phase 0.5), backlog (Phase 3.5) and validation sign-off (Phase 5) gates are Approve/Reject gates: emit Surface 1, skip Surface 2 and continue as on Approve, logged as worker-mode.md says. A contract still holding `<NEEDS USER INPUT>` is a blocker. A change that Phase 5 rates low confidence is not banked: take the Reject path (revert, record in `## History`), because worker mode has nobody to give the explicit direction it needs.
- **Boundary pause (Phase 4.5).** A change inside `owns` is auto-approved and logged. A change outside `owns` is rejected: discard that candidate as a `DEAD END`, and don't edit the file.
- **Other questions.** These are blockers, not questions: a red baseline, a `measure_command` with no parseable scalar, `BENCHMARK UNRELIABLE`, a `manual` correctness command (the Phase 1 reference and the Phase 4.7 checkpoint both need a person), and anything else that would ask. Run the leftover sweep in `phases/terminate.md` 6.5 first, then write the question and its options to `state.md`, set `Status: blocked` and end `STATUS: BLOCKED`.
- **Candidates and `owns`.** `pipeline-perf-candidate` agents run in the agent harness's isolated worktrees, built on the snapshot commit that Phase 4 stores under `refs/mz/optimize/`. The skill never runs `git worktree add`, and nothing lands on the unit's branch. Pass `owns` to every candidate as a hard constraint, and forbid it to edit the measurement command's files or the correctness tests, even when `owns` matches them. Before promotion, check the winner's patch with `git apply --numstat`: a path outside `owns` makes the candidate a `DEAD END`. Only the winner's patch is applied, with `git apply`, to the working tree, which is the unit's own worktree, so the change stays uncommitted and unstaged for the worker to commit. The per-round cleanup and the exit sweep still remove every candidate worktree, branch and ref.
- **Final message.** Emit the Phase 6 results block, then `## Files changed` (the files the banked patches touch, one per line, empty when nothing was banked), `## Verify` (run the brief's `verify` command on the final tree and give its result) and the status line last. `ALREADY WITHIN BUDGET` ends `STATUS: DONE` with nothing changed. A stop with the target unmet, or with nothing banked against a numeric target, ends `STATUS: DONE_WITH_CONCERNS` and gives the gap under `## Concerns`.
