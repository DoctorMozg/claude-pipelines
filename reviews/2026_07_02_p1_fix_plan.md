## WS-A — Path portability: no repo-relative `plugins/<name>/` literals in runtime files

**Defect class**: installed plugins do not live at `plugins/<name>/` relative to the user's cwd. Every repo-relative literal in a skill phase, agent body, or dispatch prompt breaks on a marketplace install. Verified inventory: 20 sites in mz-dev-pipe, 2 in mz-dev-git, 8 in mz-research-pipe/mz-funny (same class, swept here because the WS-D linter is repo-wide).

**Resolution patterns** (each site uses exactly one):

- **P-rel (within-skill)**: a skill referencing its own `references/` or `phases/` uses the skill-relative form the repo already uses elsewhere: `` Read `references/<file>.md` (resolve against this skill's own directory — the directory containing this SKILL.md) ``. Dispatch prompts never pass a repo-relative path: the orchestrator resolves the skill-relative path to an **absolute path at dispatch time** and passes that.
- **P-shared (within-plugin)**: references to `skills/shared/*` use the existing relative-link idiom (`[skills/shared/x.md](../shared/x.md)`), not `plugins/mz-dev-pipe/...`.
- **P-vendor (cross-plugin content file)**: a file needed by another plugin is vendored into that plugin with a marked sync region; WS-D's linter diffs the regions byte-for-byte. No runtime cross-plugin file reads remain.
- **P-name (cross-plugin agent dispatch)**: dispatch by registered agent name (already resolves across loaded plugins) plus an explicit degraded path when the providing plugin is absent.
- **P-pattern (safety rails)**: path-based rails become pattern-based rails that work in any repo.

## WS-C — MCP fallback tier: document reality

The mandated chain is gh → MCP → REST, but no mz-dev-git agent or skill has an `mcp__*` entry in its tools/allowed-tools, so tier 2 is unreachable everywhere it is documented. Two honest options were considered:

- *Add `mcp__github__*` to allowlists*: rejected — wildcard support in agent `tools:` frontmatter is unverified, MCP server presence is session-dependent, and a dropped unknown tool name fails silently (the guidelines' own `TOOL_NAME_TYPO` anti-pattern). REST is deterministic.
- **Rewrite as a conditional tier** (chosen): the chain stays three-tier *in principle*, but each executing context documents which tiers its allowlist actually exposes.

Edits:

1. **CLAUDE.md** (Plugin Authoring Conventions, gh-fallback bullet) — amend: "The MCP tier applies only where the executing context's tool allowlist actually exposes `mcp__*github*` tools. Subagents and skills whose allowlists contain no MCP tools document and use `gh` → REST, stating that MCP is unavailable to them by construction."
2. **Four agents** (`github-pr-data-fetcher.md:29,77,205`, `github-pr-info-scorer.md:30,160,169`, `github-pr-scanner.md:103`, `github-pr-reviewer.md:53`) — replace the MCP tier text with: "*(MCP tier unavailable to this agent: its tools allowlist exposes no `mcp__*` tools. Chain for this agent: `gh` → REST.)*" and renumber the REST tier accordingly; BLOCKED/red-flag lines change "gh, MCP, and REST" → "gh and REST".
3. **Two skills** (`github-review-pr/SKILL.md:82`, `github-scan-prs/SKILL.md:72-73`) — same treatment (their `allowed-tools` also expose no MCP): "try REST directly; escalate after both tiers fail."
4. **mz-dev-pipe `ask` and `debug`** — verify their chains at execution time and apply the same conditional wording where MCP is not in `allowed-tools` (ask's chain currently skips gh — fix to `gh` → REST while there).

## WS-D — Repo linter: `tests/lint_repo.sh`

New repo-root test dir `tests/` with `lint_repo.sh` (bash, no deps beyond grep/diff/awk), run by CI-minded users and **invoked by `set_versions.sh` before bumping** (refuse to bump on FAIL — same fail-loudly ethos as the existing count verification). Registered in the repo README.

Checks — **FAIL-level**:

- **L1 status-enum** (repo-wide generalization of the P0 smoke check): no `Status:` value of `completed|in_progress|complete_with_residuals` in any `plugins/*/skills/**/*.md`; exclusions: `shared/state-schema.md`, `shared/resume-protocol.md`.
- **L2 path literals**: no `plugins/mz-[a-z-]+/` literal in any file under `plugins/*/skills/**` or `plugins/*/agents/**`; exclusions: lines inside a `SYNC-REGION` header (the vendored-copy pointer names its source) and README.md files.
- **L3 agent-name resolution**: every backticked token matching a dispatch context (`Agent(<name>)`, or `dispatch`/`Launch the` within the same line as a backticked kebab-token that matches an existing agent-name prefix) must resolve to a file in some `plugins/*/agents/`. Universe = actual agent filenames; heuristic contexts only, to avoid the phantom-token trap (`pipeline-level` prose) the existing smoke Check 1 has.
- **L4 sync-region byte-diff**: for each declared SYNC-REGION pair (initially: `blinded_lenses` in mz-dev-pipe ↔ mz-dev-git; `state-schema` — see below), the content between markers must be byte-identical.
  - Prerequisite: restructure `guidelines/STATE_SCHEMA.md` and `plugins/mz-dev-pipe/skills/shared/state-schema.md` so the normative body (required-keys table, ledger discipline, example, migration table, mismatch policy) sits inside a shared SYNC-REGION; each file keeps its own short preamble outside the region. This converts the currently un-diffable reworded mirror into a checkable one.

Checks — **WARN-level** (violations exist until P2; flip to FAIL when P2 lands):

- **L5 budgets**: SKILL.md ≤150 lines; `phases/*` and `references/*` ≤400; frontmatter `description` ≤250 chars.
- **L6 constants registry** (dev-pipe only): every `MAX_*`/`*_CAP` constant in a SKILL.md Constants block appears in `shared/iteration-limits.md`'s table.
- **L4w checklist parity**: item count of `construct-skill/references/pre-publish-checklist.md` equals the checkbox count of `guidelines/SKILL_GUIDELINES.md` §23.

Output shape mirrors `run_smoke.sh` (pass/fail counters, named failures, non-zero exit on any FAIL). `set_versions.sh` gains, before its first edit: `"$(dirname "$0")/tests/lint_repo.sh" || { echo "lint failed — fix before bumping"; exit 1; }`.
