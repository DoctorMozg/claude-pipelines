## WI-6 — Hook script fixes (mz-dev-base + mz-dev-pipe)

### 6a. `plugins/mz-dev-base/scripts/session-start.sh` — stop injecting a silently truncated blob

Current behavior: `head -c 8000` of a 10,850-char SKILL.md → every session gets a routing map cut mid-table, no marker, plus ~2 KB of frontmatter/Overview/Verification noise. Rewrite the extraction:

```bash
#!/usr/bin/env bash
set -eo pipefail
# SessionStart (once: true) — injects the using-mozg-pipelines routing TABLE only.
SKILL_FILE="${CLAUDE_PLUGIN_ROOT:-}/skills/using-mozg-pipelines/SKILL.md"
MAX_LINES=200
MAX_CHARS=8000

command -v jq >/dev/null 2>&1 || exit 0
[[ -f "$SKILL_FILE" && -s "$SKILL_FILE" ]] || exit 0

# Routing table lives under "## Techniques"; extract that section only.
content=$(awk '/^## Techniques/{f=1;next} /^## /{f=0} f' "$SKILL_FILE" | head -n "$MAX_LINES") || exit 0
[[ -n "$content" ]] || exit 0
if (( ${#content} > MAX_CHARS )); then
  content="${content:0:$MAX_CHARS}
...[truncated]"
fi
printf '%s' "$content" | jq -Rs \
  '{hookSpecificOutput: {hookEventName: "SessionStart", additionalContext: ("Mozg pipelines routing map (using-mozg-pipelines):\n" + .)}}' || exit 0
exit 0
```

Notes: keeps `set -eo pipefail` but now with the `${CLAUDE_PLUGIN_ROOT:-}` guard and a justification comment; adds the missing `MAX_LINES` constant, visible truncation marker, jq-missing guard, and `|| exit 0` on every path per HOOKS_GUIDELINES failure discipline. **Check the actual section heading** before finalizing — if the routing table lives under a different `##` in that SKILL.md, anchor the awk to it (or to the first markdown table).

### 6b. `plugins/mz-dev-pipe/scripts/detect-tooling.sh` — fix inverted Python precedence

Lines ~106–130: sequential unguarded `grep -q X && VAR=` means **last match wins** (a pyproject.toml containing both `[tool.ruff]` and the string "pylint" reports pylint; any "unittest" mention overrides pytest). The JS section (lines 160–172) already does it right with `${VAR:-}` first-match guards. Mirror that pattern; intended priority = most-specific first:

```bash
grep -q 'pytest'   ... && PY_TEST="pytest"
grep -q 'unittest' ... && PY_TEST="${PY_TEST:-python -m unittest}"

grep -q '\[tool\.ruff\]' ... && PY_LINT="ruff check"
grep -q 'flake8'         ... && PY_LINT="${PY_LINT:-flake8}"
grep -q 'pylint'         ... && PY_LINT="${PY_LINT:-pylint}"

grep -q '\[tool\.ruff\.format\]' ... && PY_FMT="ruff format"
grep -q '\[tool\.black\]'        ... && PY_FMT="${PY_FMT:-black}"
grep -q 'autopep8'               ... && PY_FMT="${PY_FMT:-autopep8}"

grep -q '\[tool\.mypy\]' ... && PY_TYPE="mypy"
grep -q 'pyright'        ... && PY_TYPE="${PY_TYPE:-pyright}"
grep -q 'pytype'         ... && PY_TYPE="${PY_TYPE:-pytype}"
```

(The existing `[[ -z "$PY_FMT" ]] && grep -q 'ruff' … && PY_FMT="ruff format"` fallback line stays, unchanged.) Package-manager detection already uses `if/elif` — leave it.
